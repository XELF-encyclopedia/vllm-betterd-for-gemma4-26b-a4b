# Gemma-4-26B-A4B NVFP4 on vLLM 实测报告（修订版）

> 日期：2026-10-31
> 硬件：RTX 6000D（83.6 GiB / 1,281 GB/s / ¥6.46 时租）
> 软件：vLLM 0.32.0 / torch 2.14.1+cu130 / transformers 5.19.0
> 模型：`Deaquay/G4-MeroMero-26B-A4B-NVFP4`（15.30 GB，无审查）

> **⚠️ 修订说明**：初版报告的并发数据是错的。初版用「分波次」方式跑并发（`for c0 in range(0,conc,16)` + 每波 16），实际上并发一直是 16，所以得出「TPS 在 1,400 就封顶」的错误结论。本版用真并发重测。

---

## 一、结论

**vLLM + NVFP4 + Gemma-4-26B-A4B 在这张卡上能跑到 5,992 TPS（512 真并发零失败），是 A3B 的 2.3 倍，成本只有 A3B 的 44%。**

代价是**单流速度**：高并发下每路只有 14 tok/s。

## 四、三个关键机制

### ① TTFT 极小且几乎不随并发恶化

```
c1: 0.03s → c512: p50 1.08s / p95 2.11s
```

原因：**prefix caching**。约 1,400 token 的 system prompt 在所有请求间共享，prefill 只处理新消息。**实测 8K 上下文 prefill 速度 12,332 tok/s。**

RP 场景 TTFT 从来不是瓶颈，瓶颈是 decode 时间。

### ② 单流速度随并发下降，但聚合持续上升

```
单流: 185 → 58 (c64) → 24 (c256) → 14 (c512)
聚合: 183 → 3,139 → 5,226 → 5,992
```

**这是正常的排队行为。** 关键在于「聚合还在涨」的区间有多宽 —— 到 c384 都还在涨（+8.7%），说明调度效率很高。

### ③ 只有 128 个专家，权重读取提前饱和

batch 16 时已激活 65% 的专家，batch 48 时 95%。所以加并发主要是加「产出」而不是加「读取」，这是吞吐能线性涨到 c384 的根本原因。

**GPU 在 c256 时 100% util 但只有 334W（上限 600W）** —— NVFP4 张量核非常省电，瓶颈是显存带宽不是算力。

## 五、CoT（thinking）实测

| | thinking OFF | thinking ON |
|---|---|---|
| 耗时 | 4.8s | **9.2s** |
| 输出 token | 644 | **1,639（2.5x）** |
| 汉字数 | 609（76%） | 559（13%） |
| 开头 | 直接中文 RP | `thought` + 英文推理 |
| **结尾正文** | **中文 RP + 状态表** | **中文 RP + 状态表** ✅ |

**英文 CoT 确实能产出中文输出**（和 DeepSeek 一样）。**但代价是 2.5 倍 token、1.9 倍延迟，且 `thought` 段落会出现在原始输出里**（前端需剥离）。

**从内容看两边最终正文质量接近，所以默认关闭是对的。**

## 十、踩坑记录

| 坑 | 现象 | 根因 | 解决 |
|---|---|---|---|
| **并发测试分波次** | 得出「TPS 1,400 封顶」的错误结论 | `for c0 in range(0,conc,16)` 每波只开 16 | 一次性 `ThreadPoolExecutor(max_workers=conc)` 发全部请求 |
| **16 段 curl 互相覆盖** | 7 GB 进度归零 | 用 `-o` 没用 `-C -`，多进程写同一文件 | `aria2c -x16 -s16 -c`（单文件多连接 + 文件锁）|
| **`pkill -f "脚本名"`** | 脚本无输出直接退出 | pkill 匹配到脚本自身命令行 | `pgrep -x` 精确匹配进程名 |
| **文件大小常量写错** | 流水线永远等不到完成 | 16,459,501,568 ≠ 实际 16,423,500,596 | 用 aria2 控制文件消失判断 |
| **`du -sb` 看 sparse 文件** | 显示 100% 实际 3% | `-b` 是表观大小 | 用 aria2 日志的进度百分比 |
| **grep 漏 GiB** | 误判下载卡死 | 正则只匹配 `MiB` | 写 `[0-9.]+(MiB\|GiB)` |
| **aifasthub 速度波动** | 13.5 → 1.2 MB/s | 跨境链路拥塞（302 跳 `us.aws.cdn.hf.co`），非平台限速 | aria2 多连接 + 断点续传 |
