## 一、核心结论：聚合 TPS 破 2,500，KV 占用精准减半

在 **12,107 token 真实 RP 上下文**（每个请求插入独立 UID 扰动，彻底打破 Prefix Cache 伪共享）+ **`max_tokens=4096`** 的严苛长输出测试下：

1. **KV 占用压降至 61.59 KB/token**：原 bf16 为 118~123 KB/token，FP8 KV 实现 **1.92x 压缩（精准腰斩）**。
2. **KV 池容量突破 103 万 Token**：从原先的 51.5 万 token 翻倍至 **1,031,891 tokens**。
3. **聚合 TPS 从 997 飙升至 2,574 TPS（提升 2.58 倍）**：
   - 原 bf16 在 12K 下并发到 44 路就因 KV 耗尽而见顶（997 TPS）；
   - 新 FP8 KV 轻松承载至 **80 真实高并发零失败**，聚合 TPS 达到 **2,574 TPS**！
4. **延迟表现惊艳**：
   - 48 并发下，首字延迟（TTFT）p95 仅 **1.48 秒**；
   - 80 并发下，TTFT p95 仅 **2.62 秒**（完全在用户“5秒内无感”黄金区间）。

## 三、显存占用与 vLLM Gemma 优化核算

### 1. 显存开销精确拆解
- GPU 可用 KV 显存：**60.61 GiB（63,554,191 KB）**
- GPU KV 总 Token 数：**1,031,891 tokens**
- **当前单 Token 真实占用**：
  $$\frac{63,554,191 \text{ KB}}{1,031,891 \text{ tokens}} = \mathbf{61.59 \text{ KB/token}}$$
  *(原 bf16 实测为 118.0 ~ 123.2 KB/token，压缩率 49.8%)*

### 2. vLLM 原生 Gemma-4 优化生效机制
通过源码与日志核验，当前实例已自动启用了以下 vLLM 原生混合架构特性：
1. **Multi-KV Group 分组机制**：
   - Gemma-4 架构包含 25 层滑窗（1024 窗口）与 5 层全局全注意力。
   - vLLM 成功将其聚类为 6 个 KV Cache Group：`kv cache group sizes (16, 16, 16, 16, 16, 32)`。
   - 滑窗层不再按整段 12K 线性分配，显著节省了中间 25 层的显存占用。
2. **Blackwell sm_120 专属加速算子**：
   - **MoE 核心**：启用了 `FLASHINFER_CUTLASS` 专属 NVFP4 矩阵乘内核。
   - **采样器**：启用了 FlashInfer 原生 top-p / top-k 高速采样。
   - **注意力算子**：采用针对混合注意力调优的 `TRITON_ATTN`。
